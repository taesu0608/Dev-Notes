# 1. 원형 큐
- 선형 [[큐 (Queue)]]의 단점을 보완한 자료구조
![[Pasted image 20250813165504.png]]
## 1.1. 구조
- `rear`: 데이터가 입력되는 위치(다음에 요소를 넣을 빈 칸)
    - `enqueue`: 데이터 삽입 → `(rear + 1) % arraySize`로 이동
- `front`: 데이터가 출력하는 위치(다음에 꺼낼 요소가 있는 칸)
    - `dequeue`: `front` 위치의 데이터 제거 + 반환 → `(front + 1) % arraySize`로 이동
    - `getFront`/`peek`: `front` 위치의 데이터를 제거하지 않고 반환
- `empty`: 큐가 비었는지 확인
    - ex) `front == rear` (한 칸 비우는 구현 기준)
>front와 rear의 위치가 같다는 것은 채워진 큐의 size가 0 을 의미
- `full`: 큐가 가득 찼는지 확인
    - ex) `(rear + 1) % arraySize == front` (한 칸 비우는 구현 기준)
> 다음 데이터 입력 위치가 데이터 출력 위치임을 의미

**n 사이즈의 원형 큐는 n - 1 만큼 사용 가능**
### Cf) 빈 상태와 포화 상태
1. 빈 상태 rear == front
2. 포화 상태 rear + 1 % arraySize = front
> rear은 요소를 다음에 넣을 곳 (빈칸)
> front는 요소를 이번에 꺼낼 곳 (채워진 칸)을 의미하기에
> 두 상태의 포함관계 때문에 n 사이즈의 원형큐 n-1만큼 밖에 사용하지 못한다.
> 
> 1. 빈상태는 다음에 요소를 넣을 곳과 이번에 요소를 꺼낼 곳이 같다는 의미이다.
>    즉, "이번에 꺼낼 곳은 빈킨이다." 혹은 "다음에 넣을 곳은 현재 꺼낼 위치와 동일하다" 로 해석된다.
>    
> 2. 포화 상태를 rear == front로 표현을 한다면
>    결국 rear == front의 상태는 두가지 중첩 상태를 표현하게되어 불가능하다.

# 2. 특징
- 고정 크기 배열 기반
- 모듈로 연산 사용
	- `(index + 1) % arraySize`
- 한 칸 비움 방식
	- `full` 과 `empty` 상태 구분을 위해 보통 한 칸을 사용하지 않음
- FIFO(First-In First-Out)
	- 큐의 기본 원칙 유지
- 포인터 관리로 데이터 이동 없음
	- 삽입/삭제 시 요소를 실제 옮기지 않고, 포인터만 변경
