
# 1. 공유 자원
- 여러 프로세스가 공동으로 이용하는 변수, 메모리, 파일
- 여러 프로세스가 공동으로 이용하기에, CRUD 시점에 따라 결과가 **비결정적(non-deterministic)** 으로 나타날 수 있다.
- **경쟁 조건 발생**: 2개 이상의 프로세스가 공유 자원을 병렬적으로 읽거나 쓰는 상황
- 동일한 프로세스 내부에서 작업하는 모든 스레드가 사용하는 힙 영역이나 메서드 영역도 공유자원이다.

# 2. 임계 구역(Critical Section)
- 공유 자원 접근 순서에 따라 실행 결과가 달라지는 프로그램의 영역
- 임계 구역에서는 프로세스들이 동시 작업 불가

### Cf) 생산자-소비자 문제
- 유한한 크기의 버퍼를 공유하는 생산자와 소비자 간에, **동기화 문제**로 인해 버퍼의 실제 상태와는 다르게 동작하는 경우가 발생할 수 있다.  
	- 전제) 크기가 4인 원형 버퍼, 상품의 총수를 저장하는 전역버퍼 sum
	1. 생산자가 버퍼 4번째 칸에 값을 저장. sum은 아직 4로 바뀌기 전 (현재 sum = 3)
	2. 소비자가 값 하나 삭제. sum을 아직 바꾸지 못함(현재 sum = 3)
	3. 이 상태에서 생산자의 `sum += 1` 과 소비자의 `sum -= 1`이 동시에 실행되었을 때, 두 작업이 `sum = 3`일때 기준으로 실행되게 된다.
	4. 이후 sum은 2 혹은 4의 값을 가지게 된다.

# 3. 상호 배제 (Mutual Exclusion)
- 한 프로세스가 임계 영역에 들어가면 다른 프로세스는 임계 영역에 들어가지 못하도록 OS가 통제
## 3.1. 상호배제를 위한 기본 처리구조
	1. 진입 영역(상호 배제 사전처리)
	2. 임계 영역
	3. 출구 영영(상호 배제 사후처리)
	4. 잔류 영역
