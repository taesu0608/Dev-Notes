### Cf) 컨테이너 오케스트레이션
- 시스템 전체를 통괄하고 여러 개의 컨테이너를 관리하는 일


# 02 마스터 노드와 워커 노드

마스터 노드: 전체적인 제어를 담당
워커 노드: 실제 동작을 담당

마스터 노드에서 컨테이너를 실행하지 않음
	컨테이너 엔진(Ex) 도커 엔진) 불필요

클러스터: 마스터 노드와 워커 노드로 구성된 일군의 쿠버네티스 시스템

준비 환경
- 마스터 노드
	1. 쿠버네티스 엔진
	2. CNI(가상 네트워크 드라이버)
		- Ex) flannel, Calico, AWS VPC CNI
	3. [[etcd]]
		- key-value 데이터베이스
- 워커 노드
	1. 쿠버네티스 엔진
	2. Conatiner Engine

### Cf) 도커 컴포즈와 쿠버네티스의 차이 with etcd
- 쿠버네티스의 정의 파일(manifast file)이 데이터베이스로 관리됨
- manifast를 커맨드 수정가능
- 커맨드를 통하여 직접 컨테이너 수정 시
	- manifast은 유지
	- etcd 정보 변경
	-> manifast 와 etcd의 정보의 차이 발생

## Controll Plain
- 쿠버네티스 클러스터에서 전체 시스템을 **제어하고 조율하는 컴포넌트들의 집합**
- 스터 노드는 Controll Plain을 통해 워커 노드를 관리함

## 마스터 노드의 컨트롤 플레인 구성

| 항목                         | 내용                                      |
| -------------------------- | --------------------------------------- |
| `kube-apiserver`           | 외부와 통신하는 프로세스, `kubectl`로부터 명령을 전달받아 실행 |
| `kube-controller-manager`  | 컨트롤러를 통합 관리, 실행                         |
| `kube-scheduler`           | 파드를 워커 노드에 할당                           |
| `cloud-controller-manager` | 클라우드 서비스와 연동해 서비스를 생성                   |
| `etcd`                     | 클러스터 관련 정보 전반을 관리하는 데이터베이스              |

## 워커 노드의 구성
| 항목             | 내용                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| **kube-let**   | 마스터 노드에 있는 **kube-scheduler**와 연동하며 워커 노드에 파드를 배치하고 실행한다. 또한 실행 중인 파드의 상태를 정기적으로 모니터링하며 **kube-scheduler**에 통지한다. |
| **kube-proxy** | 네트워크 통신의 라우팅 메커니즘                                                                                                 |

## 쿠버네티스는 항상 '바람직한' 상태 유지
- '바람직한 상태'를 YAML 파일에 정의하고, 자동으로 컨테이너를 생성/삭제 하면서 상태를 유지하는 것
- 쿠버네티스의 기능 = 도커 컴포즈(컨테이너 생성 및 조작) + 모니터링을 통한 상태 유지

### Cf) 로드 밸런서와 클라우드 컴퓨팅
- 쿠버네티스 + 로드밸런서 컨테이너 조절로 대규모 트래픽 대응 혹은 리소스 절약에 관여할 수 있다.

# 03 쿠버네티스의 구성과 관련 용어

## 파드(pod)
- 파드 = n개의 컨테이너 + m개의 볼륨
	- n >= 1

### Cf) 파드의 볼륨과 컨테이너의 볼륨
- 도커 수준의 볼륨은 컨테이너가 단독으로 쓰는 도구
- 파드 수준의 볼륨은 Pod내 컨테이너들이 정보를 공유하기 위해 사용하는 것


## 서비스(service)
- 여러 개의 파드를 접근하기 위한 추상화 객체
	- 파드에 요청을 배분을 담당
- 한 서비스가 관리하는 파드는 동일한 구성
- 논리적 묶음을 단위로 관리함
	- 여러 개의 워커 노드(물리적 서버)이더라도 모두 관리
![[IMG_0021 1.jpg]]

### 서비스의 역할
- 로드 밸런서
	- 분리된 워커노드간의 컨테이너는 로드밸런싱이 불가함
	- 실제적으로 로드밸런서 혹은 인그레스(ingress)가 담당함
- [[cluster IP]] : 고정된 IP

## 레플리카세트(ReplicaSet)
- **동일한 파드(Pod)를 지정한 수만큼 유지**해주는 쿠버네티스의 컨트롤러 객체
#### 역할
- 파드 유지
	- 정의 파일에 정의된 파드의 수에 따라 관리
- 자동 복구
	- 파드 수 부족시 파드 보충
##### 동일한 구성의 파드 = 레플리카 라고함

## 디플로이먼트(Deployment)
- 파드의 배포(Deploy)를 관리하는 요소
- 파드에 대한 정보를 가짐(이미지, 제약, etc)

### Cf) 상하관계
디플로이먼트 > 레플리카세트 > 파드

## 그외 리소스
| 한글 리소스 이름 (영문명)                    | 설명                                  |
| ---------------------------------- | ----------------------------------- |
| 파드 (Pods)                          | 컨테이너와 볼륨을 합친 실행 단위                  |
| 파드 템플릿 (Pod Template)              | 파드 배포 시 형틀 역할을 하는 정의 구조             |
| 레플리케이션컨트롤러 (ReplicationController) | 파드의 복제 개수를 제어하는 초기 리소스              |
| 리소스 쿼터 (ResourceQuota)             | 네임스페이스 내에서 리소스 사용량 제한 설정            |
| 비밀값 (Secret)                       | 키, 인증정보 등 민감한 데이터를 안전하게 저장 및 제공     |
| 서비스 어카운트 (ServiceAccount)          | 파드 등 리소스가 API 접근 시 사용할 사용자 자격 정보 관리 |
| 서비스 (Service)                      | 파드 집합에 대한 요청을 라우팅해주는 네트워크 추상화       |
| 데몬세트 (DaemonSet)                   | 각 워커 노드마다 하나씩 파드를 생성 및 유지           |
| 디플로이먼트 (Deployment)                | 파드의 배포 및 업데이트를 선언적으로 관리             |
| 레플리카세트 (ReplicaSet)                | 지정된 수의 파드가 항상 실행되도록 유지              |
| 스테이트풀세트 (StatefulSet)              | 고유 네트워크 ID와 저장소를 가진 상태 저장형 파드 관리    |
| 크론잡 (CronJob)                      | 정해진 스케줄에 따라 파드를 주기적으로 실행            |
| 잡 (Job)                            | 단일 작업을 위한 파드를 실행하고 완료 시 종료          |

### Cf) 오브젝트와 인스턴스
etcd 관리 대상 = 오브젝트
실제 생성된 것 = 인스턴스

### 주요 메타데이터
| 항목               | 내용                                                                 |
|--------------------|----------------------------------------------------------------------|
| name               | 리소스의 이름, 문자열로 된 유일 식별자                              |
| namespace          | 리소스를 세분화한 DNS 호환 레이블                                   |
| uid                | 유일 식별자                                                          |
| resourceVersion    | 리소스 버전                                                          |
| generation         | 생성 순서를 나타내는 번호                                            |
| creationTimestamp  | 생성 일시                                                            |
| deletionTimestamp  | 삭제 일시                                                            |
| labels             | 임의의 레이블                                                        |
| annotation         | 리소스에 설정할 값 (선택 대상은 아님, 검색 조건에는 사용되지 않음) |
