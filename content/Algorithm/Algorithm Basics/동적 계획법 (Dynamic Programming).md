# 1. DP
- **정의**: 하나의 큰 문제를 여러 개의 작은 문제로 나누어서 그 결과를 저장하여 다시 큰 문제를 해결할 때 사용
- **이유**: 일반적인 재귀(Native Recursion) 방식과 DP와 유사하지만, 일반적인 재귀는 동일한 작은 문제들이 반복되어 오버헤드를 야기

### Cf) 피보나치 수열: 재귀와 DP의 차이
- 일반 피보나치 수열 점화식
$$F(n)=F(n−1)+F(n−2),\quad F(0)=0,\quad F(1)=1$$
- 재귀 시간복잡도: $O(2^n)$
- DP 시간복잡도: $O(n)$

## 1.1. DP 일반적인 설계 과정
1. 문제를 작은 문제로 분해(Subproblem 정의)
	- 작은 문제 정의 시  
		- 현재 상태를 계산할 때  최소한의 이전 상태들만 직접 참조하도록 정의한다.  
		- **더 이전 상태의 영향은  이전 상태(dp[i-1], dp[i-2] 등)에 이미 포함**을 보장되도록 설계할 것
	- 대부분의 경우  
		- 가능한 경우를 나누어  현재 상태를 이전 상태의 조합으로 표현한다.
2. 상태(State) 정의
	- DP의 자료구조 정의
	- DP의 Index의 의미
		- 상태변화에 따른 Index 변경 기준 설정
	- DP 저장 값 정의
3. 점화식(Recurrence relation)
	- 현재 상태를 이전 상태들로 표현
	- **Cf) 이전 상태의 문제는 기해결된 문제로 취급**
4. 초기값(Base case)설정
	- 초기 상태 설정
	- **점화식 시작$(n = 1, 2, etc)$을 설정**
5. 계산 순서 결정
	- Bottom - up: 초기값 부터 마지막 상태까지 표현
	- Top-down: 마지막 값부터 추적
		- 재귀 + 메모이제이션(Recursion + memoization)
			- [[재귀 함수(Recursive Function)]]: 자기 자신을 호출하는 함수
			- 메모이제이션: 기저장된 값은 활용하고 신규 저장된 값을 기록

## 2.2. Bottom-Up/ Top-Down
### 2.2.1. Bottom-Up
- 아래에서 부터 계산을 수행하고 누적시켜 전체 큰 문제를 해결하는 방식
- **Tabulation** 
	- 기저 상태(`dp[0]`) 부터 목표 상태(`dp[n]`) 까지 반복문을 활용해 결과를 도출하는 방식
	- *table-filling*: 즉 Table에 저장된 값을 직접 접근하여 재활용하므로 `Tabulation` 이라는 명칭이 붙음

### 2.2.2. Top_Down
- 위에서 부터 계산을 호출을 시작하여 `dp[0]`의 상태까지 내려간 다음 해당 결과 값을 재귀를 통해 전이시켜 재활용하는 방식
- 이 때, 이미 이전에 계산이 된 경우, 단순히 메모리에 저장되어 있던 데이터를 활용
