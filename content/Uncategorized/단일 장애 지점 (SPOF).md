# 1. 단일 장애 지점(Single Point Of Failure)
- 시스템이나 네트워크의 한 부분이 고장 났을 때 전체 시스템이 마비되는 현상
- 다양한 계층에서 문제가 발발되며 그에 따른 해결 방안들이 존재

## 1.1. 코드 레벨 SPOF
### 1.1.1. 과도한 의존성
- **문제**: 특정 외부 서비스 혹은 API에 의존할 경우
	- Ex) 결제 처리, 사용자 인증
- **해결책**
	1. 외부 서비스에 대한 타임 아웃 설정
	2. [[서킷 브레이커 (Circuit Breaker Patterm)]] 패턴
	3. 여러 서비스 제공자 사용을 통해 의존성 분산

## 1.2. 단일 데이터베이스 SPOF
- **문제**: 하나의 데이터베이스에 의존하게 되면 서버 장애 시 데이터 중단 및 전체 시스템 악영향
- **해결책**
	1. 데이터베이스 레플리케이션(Database Replication)
		- Master - Slave 구조로 마스터 서버와 동일한 데이터를 지닌 슬레이브 서버 운용
		- 이벤트 소싱: 마스터 서버의 CRUD 및 조작 로그를 슬레이브 서버에 저장 및 실행 시켜 데이터를 유지
	2. [[샤딩 (Sharding)]]
		- 대용량 데이터베이스를 관리하기 쉬운 작은 파티션(여러 개의 DB서버)로 나누는 것
	3. 클러스터링
		- 여러개의 DB를 수평적인 구조로 구축
		- DB 저장 및 수정 시행 전 DB끼리 소통을 하여 일관성을 유지한 방법

## 1.3. 서버 레벨 SPOF
- **문제**: 하나의 서버에 의존하게 되면 서버 장애 시 서비스 제공이 어려움
- **해결책**
	1. Web Server  
		- 여러대의 서버를 운용하여 로드밸런서를 통해 서버의 장애 대응  
		- 정적 리소스(HTML, CSS, JS, 이미지 등)의 요청을 분산 처리  
		- Reverse Proxy 역할을 통해 클라이언트의 요청을 내부 WAS로 전달  
		- 외부에는 Web Server만 노출되어 WAS를 직접 노출하지 않아 보안 계층 분리가 가능  
  
	2. WAS  
		- 여러개의 WAS 인스턴스를 실행하여 로드밸런서를 통해 요청을 분산 처리  
		- 비즈니스 로직 처리 능력을 수평 확장(horizontal scaling)하여 동시에 더 많은 요청을 처리 가능  
		- 특정 WAS 인스턴스에 장애가 발생해도 다른 WAS가 요청을 처리하여 서비스 가용성을 유지  
		- Blue-Green, Rolling 같은 무중단 배포 전략을 적용할 수 있는 기반이 됨
