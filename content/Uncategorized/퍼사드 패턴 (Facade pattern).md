# 1. Facade
- 사전적 의미: 건축물의 정면, 건축물의 정면으로도 건축물의 목적이 나타나는 특징을 차용하여 명명함
## 1.1. 퍼사드 패턴 구조
1. Facade
	- 서브시스템 기능을 쉽게 사용하기 위해 로직을 재정리하여 높은 레벨의 인터페이스로 구성
	- 클라이언트와 서브시스템이 서로 긴밀하게 연결되지 않도록 함
2. Additional Facade
	- 퍼사드 클래스는 수의 제한이 없음
	- 접근의 제한이 없음
		- 다른 퍼사드에서도 사용 가능
		- 클라이언트에서도 직접 접근 가능
3. SubSystem(하위 시스템)
	- 수십 가지 라이브러리 혹은 클래스들
4. Client
	- 서브 시스템에 직접 접근하지 않고 Facade를 사용

### 1.1.1. Facade
- [[전략 패턴 (Strategy Pattern)]] 이나 [[팩토리 패턴 (Factory Pattern)]] 과 달리 구조가 정형화되지 않은 패턴

### 1.1.2. Additional Facade
- 재귀적 퍼사드 = Additional Facade
- Facade를 계층적으로 구현함으로써 시스템을 여러개의 Facade로 만드는 것

## 1.2. 퍼사드 패턴 특징

### 1.2.1. 사용시기
- 시스템 복잡성이 높아 간단한 인터페이스로 접근성을 높일 때
- 시스템을 사용하고 있는 외부와 결합도가 너무 높아 의존성을 낮출 때

### 1.2.2. 장점
- 하위 시스템의 복잡성에서 코드를 분리하여, 외부에서 시스템 사용이 편리해짐
- 의존성을 한곳으로 모을 수 있음
- 사용자가 Facade 클래스만 이해하여도 됨

### 1.2.3. 단점
- 퍼사드가 프로그램의 모든 클래스에 결합된 God 객체가 될 수 있음
- 추가적인 코드로 유지보수 비용이 증가함
