# 1. 모델 변환
- 서로 다른 바운디드 컨텍스트가 협력하고자 할 때, 사용자 - 제공자 관계가 생김
- 업스트림(제공자) 또는 다운스트림(사용자)가 직접적으로 컨텍스트 모델이 호환이 되지 않아 변환이 필요한 경우 아래의 방법 중 하나의 방법 사용
	- 충돌 방지 계층(ACL): 다운스트림 바운디드 컨텍스트가 구현하는 계층
	- 오픈 호스트 서비스(OHS): 업스트림 바운디드 컨텍스트가 구현하는 계층
		- 업스트림 바운디드 컨텍스트의 내부 모델을 통합하여 언어를 공표
- 두 방법을 묶어서 모델의 변환 로직이라함
- 모델 변환 로직의 구분
	- **스테이트리스 변환(statetless translation)**
		- 상태를 보존 X
	- **스테이트풀 변환(stateful translation)**
		- 상태를 보존

# 2. 애그리게이트 연동
- 애그리게이트 통신 방법 중 이벤트 발행 방식을 정리
## 2.1. 안티패턴
- 도메인 계층에서 이벤트 발행행
``` C#
public class Campaign
{
	...
	List<DomainEvent> _event;
	IMessageBus _messageBus;
	...
	
	public void Deativate(string reason)
	{
		for (l in _locations.Values())
		{
			l.Deactivate();
		}
		
		IsActive = false;
	}
	// 새 이벤트 인스턴스화
	var newEvent = new CampaignDeactivated(_id, reason);
	_events.Append(newEvent);
	_messageBUs.Publish(newEvent);
	}
}
```
- **문제점**
	- 애그리게이트에서의 도메인 이벤트 발행은 데이터베이스의 커밋시점과 일치하지 않음
	- 경합 조건 발생 시(트랜잭션 취소, 롤백) 이미 이벤트가 발행되게 된다.

#### Ex) 해결책
- 애플리케이션 계층에서 도메인 발행
	- 데이터베이스의 커밋 시점 불일치 해결
- **문제점**
	- 시스템의 안정성에 의존되어 있음
```C#
public class ManagementAPI
{
	...
	private readonly IMessageBus _messageBus;
	private readonly ICampaignRepository _repository;
	...
	
	public ExecutionResult DeactivateCampaign(CampaignId id, string reason)
	{
		try
		{
			//Datebase Commit
			var campaign = repository.Load(id);
			campaign.Deactivate(reason);
			..repository.CommitChanges(campaign);
			
			var events = campaign.GetUnpublishedEvents();
			for (IDomainEvent e in events)
			{
				_messageBus.publish(e);
			}
			campaign.ClearUnpublishedEvents();
		}
		catch(Exception ex)
		{
			...
		}
	}
}
```

## 2.2. 아웃박스 패턴(outbox pattern)
- **과정**
	- 수정된 애그리게이트의 상태와 새 도메인 이벤트는 모두 동일한 원자성 트랜잭션으로 커밋됨
		- 아웃박스 패턴
	- 메시지 릴레이는 데이터베이스에서 새로 커밋된 도메인 이벤트를 가져온다.
		- 발행되지 않은 이벤트 가져오기
	- 릴레이는 도메인 이벤트를 메시지 버스에 발행한다.
	- 성공적으로 발행되면 릴레이는 이벤트를 데이터베이스에 발행한 것으로 표시하거나 완전히 삭제
 ![[Pasted image 20250903223306.png]]
### 2.2.1. 아웃박스
관계형 데이터베이스의 트랜잭션 기능을 통해 DB내에서 이벤트 정보 + 애그리게이션 상태 정보 무결성 보장
- DB의 트랜잭션 기능 활용
	- 애그리게이트 상태 테이블과 아웃박스 테이블을 한 트랜잭션으로 운용
	1. **애그리게이트 상태 테이블**
		- 애그리게이트 상태 정보 저장
	2. **아웃박스 테이블**
		- 이벤트 발행 정보 저장

#### Ex) NoSQL 데이터베이스 경우
- NoSQL DB는 트랜잭션을 지원하지 않음
- JSON 문서의 추가 속성 outbox 존재
```JSON
{
	"campaign-id": "364b33c3-2171-446d-b652-8e5a7b2be1af",
	"state": {
		"name": "Autumn 2017",
		"publishing-state": "DEACTIVATED",
		"ad-locations": [
			...
		]
	},
	"outbut": [
		{
			"campaign-id": "364b33c3-2171-446d-b652-8e5a7b2be1af",
			"type": "campaign-deactivated",
			"reason": "Goals met",
			"published": false
		}
	]
}
```

### 2.2.2. 발행되지 않은 이벤트 가져오기
- 발행 릴레이가 새 도메인 이벤트를 가져오는 방법
- 주체 데이터베이스, 대상자 이벤트 릴레이
	1. 풀(Pull) - 발행자 풀링
		- 릴레이는 발행되지 않은 이벤트에 대해 데이터베이스를 지속해서 질의하는 방식
		- 발행되지 않는 이벤트의 반복된 질의는 데이터베이스의 성능을 저하시킴
			- Thus) Index 사용이 효율적임
	2. 푸시(Push) - 트랜잭션 로그 추적
		- 새 이벤트 추가시 발행 릴레이 호출
			- Ex) 새 이벤트 추가 시 발행 릴레이 예시
				- 트랜잭션 로그를 추적하여 변경된 레코드 알림 기능이 있는 일부 RDBMS
				- 커밋된 변경사항을 이벤트 스트림으로 노출하는 일부 NoSQL
					- AWS DynamoDB Streams

- 아웃박스 패턴은 최소 한번 메시지 배달을 보장

### 2.2.3. 사가(saga)
- 동일한 애그리게이트 경계에 두 가지 비즈니스 엔티티에 걸쳐져있는 경우
- 단계별로 애그리게이트를 변경하는 방법
- **특징**
	- 사가는 오래 지속되는 비즈니스 프로세스
		- 시간 기준이 아닌 트랜잭션 기준으로 프로세스를 다룸
	- 관련 컴포넌트에서 발생하는 이벤트를 다른 컴포넌트에 후속 커맨드를 발행
		- 해당 컴포넌트 실패 시, 적절한 보상 조치
	- 프로세스 관리자(process manager)와 혼동되기도 함
![[Pasted image 20250904001002.png]]
#### Ex)
```C#
public class CampaignPublishingSaga
{
	private readonly ICampaignRepository _repository;
	private readonly IList<IDomainEvent> _events;
	
	public void Process(CampaignActivated activated)
	{
		var campaign = _repository.Load(activated.CampaignId);
		var advertisingMaterials = campaign.GenerateAdvertisingMaterials();
		var commandIssuedEvent = new CommandIssuedEvent(
			target: Target.PublishingService,
			command: new SubmitAdvertisementCommand(activated.CampaignId,
			advertisingMaterials));
			
		_events.Append(activated);
		_events.Append(commandIssuedEvent);
	}
	
	public void Process(PublishingConfirmed confirmed)
	{
		var commandIssuedEvent = new CommandIssuedEvent(
			target: Target.CampaignAggregate,
			command: new TrackConfirmation(confirmed.CampaignId,
											confirmed.ConfirmationId));
											
		_events.Append(commandIssuedEvent);
		_events.Append(confirmed);
	}
	
	public void Process(PublishingRejected rejected)
	{
		var commandIssuedEvent = new CommandIssuedEvent(
			target: Target.CampaignAggregate,
			command: new TrackRejection(rejected.CampaignId,
										rejected.RejectionReason));
										
		_events.Append(rejected);
		_events.Append(commandIssuedEvents);
	}
}
```
### 2.2.4. 프로세스 관리자
- 프로세스 관리자는 시퀀스의 상태를 유지하고 다음 처리 단계를 결정하는 중앙 처리 장치로 정의
- 여러 이벤트의 호출을 담당하는 메서드가 존재
![[Pasted image 20250904202430.png]]
```C#
public class BookingProcessManager
{
	private readonly IList<IDomainEvent>_events;
	private BookingId _id;
	private Destination _destination;
	private TripDefinition _parameters;
	private EmployeeId _traveler;
	private Route _route;
	private IList<Route> _rejectedRoutes;
	private IRoutingService _routing;
	
	public void Initialize(Destination destination,
							TripDefinition parameters,
							EmployeeId traveler)
	{
		_destination = destination;
		_parameters = parameters;
		_traveler = traveler;
		_route = _routing.Calculate(destination, parameters);
		
		var routeGenerated = new RouteGeneratedEvent(
			BookingId: _id,
			Route: _route);
			
		var commandIssuedEvent = new CommandIssuedEvent(
			command: new RequestEmployeeApproval(_traveler, _route)
		);
		_events.Append(routeGenerated);
		_events.Append(commandIssuedEvent);
	}
	
	public void Process(RouteConfirmed confirmed)
	{
		var commanddIssuedEvent = new CommandIssuedEvent(
			command: new BookFlights(_route, _parameters)
		);
		_events.Append(confirmed);
		_events.Append(commandIssuedEvent);
	}
	
	public void Process(RouteRejected rejected)
	{
		var commandIssuedEvent = new CommandIssuedEvent(
			command: new RequestRerouting(_traveler, _route)
		);
		_events.Append(rejected);
		_events.Append(commandIssuedEvent);
	}
	
	public void Process(ReroutingConfirmed confirmed)
	{
		_rejectedRoutes.Append(route);
		_route = _routing.CalculateAltRoute(destination, parameters, rejectedRoutes);
		
		var routeGenerated = new RouteGeneratedEvent(
			BookingId: _id,
			Route: _route);
		var commandIssuedEvent = new CommandIssuedEvent(
			command: new RequestEmployeeApproval(_traveler, _route)
		);
		
		_events.Append(confirmed);
		_events.Append(routeGenerated);
		_events.Append(commandIssuedEvent);
	}
	
	public void Process(FlightBooked booked)
	{
		var commandIssuedEvent = new CommandIssuedEvent(
			command: new BookHotel(_destination, _parameters)
		);
		
		_events.Append(booked);
		_events.Append(commandIssuedEvent);
	}
}
```
