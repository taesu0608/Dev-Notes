# 1. 트랜잭션 스크립트

**시스템의 퍼블릭 인터페이스**
- 사용자가 실행 할 수 있는 트랜잭션의 모음
-> 인터페이스 = 트랜잭션의 모음

**트랜잭션**
- 여러 개의 프로시저 기반의 비즈니스 로직

## 1.1. 트랜잭션 스크립트 구현
### 1.1.1. 프로시저
- 프로시저
	- 절차지향 스크립트(procedural)로 구현
- 프로시저의 필요조건
	- 성공/실패 여부와 무관하게, 유효하지 않는 상태를 회피해야함
		- 유효하지 않는 상태 회피방법
			- 롤백
			- 보상조치
#### 변환 트랜잭션 스크립트 예시
```transaction script
DB.StartTransaction();

var job = DB.LoadNextJob();
var json = LoadFile(job.Source);
var xml = ConvertJsonToXml(json);
WriteFile(job.Destination, xml.ToString());
DB.MarkJobAsCompleted(job);

DB.Commit()
```

### 1.1.2. 트랜잭션 동작 구현 실패
#### 1. 트랜잭션 없이 여러 업데이트를 할 경우
```java
upblic class LogVisit
{
	public void Execute(Guid userId, DataTime visitedOn)
	{
		db.Execute(수정 sql1);
		db.Execute(수정 sql2);
	}
}
```
- 두번째 sql의 동작이 성공하지 못할 가능성 존재재
	- 네트워크 중단, 데이터베이스 시간 초과, 교착 상태, 프로세스 실행 서버의 충돌
#### 해결책 - 트랜잭션 없이 여러 업데이트를 할 경우
- 두 프로시저를 하나의 트랜잭션으로 만들어 해결
```java
public class LogVisit
{
	public void Execute(Guid userId, DataTime visitedOn)
	{
		try
		{
		db.StartTransaction();
		db.Execute(수정 sql1);
		db.Execute(수정 sql2);
		db.Commit();
		} catch {
		db.Rollback();
		throw;
		}
	}
}
```

#### 2. 분산 트랜잭션

### Cf) 분산 트랜잭션(Distributed Transaction)
> 분산 시스템에서 데이터 베이스의 데이터 변경 발생시 메시지 버스에 메시지를 발행하여 시스템의 다른 컴포넌트에 변경사항을 알림
> 이 때의 변경사항을 알려야 되는 작업을 분산 트랜잭션(Distributed Transaction) 이라함.

#### 2.1. 암시적 분산 트랜잭션
```java
public class LogVisit
{
	public void Execute(Guid userId)
	{
		db.Execute(방문수 증가 count문);
	}
}
```
- `LogVisit()` 실행시
	- DataBase 트랜잭션 실행
	- 사용자에게 결과 반환
##### DB에선 제대로 실행이 되었지만 사용자에게 결과 반환이 잘못된 경우
> 사용자는 다시한번 LogVisit을 실행하게 되어 추가적인 카운터 값 증가 발생

#### 2.1. 해결책 - 암시적 분산 트랜잭션
- **멱등성(idempotent)** 을 부여
	- 같은 요청을 여러 번 반복하더라도 그 결과는 매번 동일하도록 만드는 것
```java
public class LogVisit
{
	// 파라미터 추가
	public void Execute(Guid userId, long visits)
	{
		db.Execute("UPDATE Users SET visits = @p1 WHERE user_id=@p2",
					visits, userId);
	}
}
```
- 사용자에게 가지고 있는 카운터 값을 전달하도록 요청
**expected problem**
- 경합 문제 발생 시, 잘못된 카운터 저장
> visits = 6 요청, visits = 7 요청 경합 발생
> visits = 7 , visits = 6 순서로 도달
> 최종적으로 6 + 1 인 visits = 7 이 저장

#### 2.1. 해결책 - 낙관적 동시성 제어(optimistic concurrency control)
```java
public class LogVisit
{
	public void Execute(Guid userId, long expectedVisits)
	{
		// 사용자가 가진 counter 값과 비교후 기저장된 counter와 같을 때 counter 증가
		db.Execute(@"UPDATE Users SET visits=visits +1
					WHERE user_id=@1 and visits = @p2",
					userId, visits);
	}
}
```
- 사용자가 `LogVisit` 작업 호출 전 카운터의 현재 값을 읽고 매개변수로 전달
- 전달된 매개변수가 DB의 카운터와 동일한 경우 카운터 값 업데이트

# 2. 액티브 레코드
- 트랜잭션 스크립트 패턴과 마찬가지로 비즈니스 로직이 단순한 경우 사용
	- 트랜잭션 스크립트 패턴과 다르게 매핑시 복잡성을 해소함
**목적**
- 데이터베이스에 직접 접근 하지 않고 액티브 레코드 객체를 조작
	- 조작단계에서 부가적인 작업 가능
		- 영속화 (필수작업)
		- 유효성 검사
		- 객체 데이터 조작
- 메모리상 객체와 데이터베이스 스키마를 매핑하는 과정을 캡슐화 하는 패턴
**기능**
- 자료구조와 동작의 분리
	- 자료구조의 수정 또한 동작으로써 처리함
		- Ex) getter, setter
## 2.1. 액티브 레코드 구현
- 액티브 레코드
	- 액티브 레코드 패턴을 위한 전용 객체
```java
public class CreateUser
{
	//여러 파라미터가 아닌 DTO 형태의 전송 객체 존재
	public void Execute(userDetails)
	{
		try
		{
			db.StartTransaction();

			var user = new User();
			user.Name = userDetails.Name;
			user.Email = userDetails.Email;
			user.Save();
			_db.Commit();
		} catch {
			_db.Rollback();
			throw;
		}
	}
}
```

### Cf) 엑티브 레코드의 사용 경우
- 데이터베이스 접근을 최적화하는 트랙잭션 스크립트 패턴
	- 간단한 작업에 유리(유효성, CRUD)
- 지원 하위 도메인, 일반 하위 도메인, 외부 솔루션의 연동, 모델 변환
