# 비즈니스 도메인
- 기업의 주요 활동 영역

# 하위 도메인(subdomain)
- 비즈니스 도메인의 목표를 달성하기 위한 세부적인 영역 
	1. 핵심 하위 도메인(core subdomain)
		- 차별성 = 경쟁업체와 다르게 수행하고 있는 것
			- New = 새로운 서비스 발명
			- Efficient = 기존 프로세스 최적화로 비용을 줄임
		- Ex) 스마트 최적화, 비즈니스 노하우, 지적 재산, etc.
		- 수익에 직접적인 연관에 미치는 것
		- 복잡성 → 진입장벽↑ → 장기적 경쟁력 확보
		- 기술 솔루션이 경쟁 우위의 원천이 아닐 수 있음
			- Ex) 보석 제조업체는 보석 유통 및 플랫폼이 아닌 디자인에서 경쟁 우위가 만들어짐
	2. 일반 하위 도메인(generic subdomain)
		- 모든 회사가 같은 방식으로 수행하는 비즈니스 활동
		- 차별성 X
			- New와 Efficient가 더 이상 필요하지 않음
			- Ex) 권한 인증 서비스, 이메일 인증 서비스, etc.
	3. 지원 하위 도메인(supporting subdomain)
		- 회사의 비즈니스를 지원하는 활도
		- 차별성 X
			- Ex) [[ETL]](extract, transform, load: 추출, 변환, 로드), CRUD
# 하위 도메인 비교
1. 경쟁우위
	- 핵심 하위 도메인만이 경쟁 우위를 제공
2. 복잡성
	- 핵심 하위 도메인> 일반 하위 도메인> 지원 하위 도메인
	- Cf) 도메인끼리의 분류 방법
		- 해당 도메인을 외주화를 할 수 있는가?
3. 변동성
	- 핵심 하위 도메인 > 지원 하위 도메인
4. 솔루션 전략
	- 핵심 하위 도메인
		- 중요도, 복잡성이 큼 -> 숙련된 개발자
		- 변동성이 가장 큼 -> 가장 진보된 엔지니어링 기술
	- 일반 하위 도메인
		- 기 존재하는 제품, 오픈소스 솔루션 채택
	- 지원 하위 도메인
		- (RAD: rapid application development) 신속한 애플리케이션 개발 프레임워크 사용
			- 우발적 복잡성(accidental complexity)을 낮춤

# 하위 도메인 경계 식별
## 하위 도메인 정제
- 큰 범위의 하위 도메인 또한 세부 사항으로 나눌수 있음
	- But) 무한정 하위 도메인을 파헤칠 수 없음

## 응집된 유스케이스를 하위 도메인으로
- 하위 도메인은 응집된 유스케이스의 집합과 유사함

# 도메인 전문가 (domain expert)
- 비즈니스 도메인 권위자
	- 비즈니스를 대표하는 자
	- 비즈니스 문제를 처음 파악한 자
	- 요구사항을 제시하는 사람
	- 소프트웨어의 최종 사용자
- 전문성 범위는 다양함
	- 전체 비즈니스를 상세히 이해 ~ 특정 하위 도메인을 전문
