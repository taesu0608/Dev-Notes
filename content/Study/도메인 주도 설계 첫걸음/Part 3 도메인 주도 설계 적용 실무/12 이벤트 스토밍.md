# 1. 이벤트 스토밍 (EventStorming)
## 1.1. 이벤트 스토밍이란
**이벤트 스토밍**
- 여럿이 비즈니스 프로세스에 관해 브레인스토밍을 하는 것
	- 신속한 모델링
	- 도메인 지식 공유
- 범주(scope)가 존재
	- scope = 참가자가 다룰 비즈니스 프로세스
	- scope는 모델의 모든 구성요소를 비즈니스 프로세스의 작동 방식이 설명될 때까지 단계별로 액터, 커맨드, 외부 시스템들의 개념을 추가해 개선해야함

**참가자**
- 다양한 그룹의 사람이 참가
- 참가자의 규모가 너무 커지면 모든 참가자가 과정에 기여하는것이 어려움

**준비물**
1. 모델링 공간
2. 포스트잇
	- 다양한 색
3. 마커
4. 간식
5. 회의실

## 1.2. 이벤트스토밍 과정
1. 자유로운 탐색
	- 도메인 이벤트(domain event)을 브레인 스토밍하는 것으로 시작
	- 이미 발생한 일
2. 타임라인
	- 정상 시나리오(happy path scenario)부터 시작
3. 고충점
	- 이벤트스토밍 세션 과정에서 논의가 비효과적인 것을 표기
		- 병목구간, 자동화가 필요한 수작업, 도메인지식이 없는 경우
		- Ex) 항공권 요금은 어떻게 비교되는가?
4. 중요 이벤트
	- 중요 이벤트(pivotal event) 식별
		- 컨텍스트나 국면이 바뀌는 비즈니스 이벤트
5. 커맨드
	- 커맨드
		- 무엇이 이벤트 또는 이벤트의 흐름을 시작하게 하는지 설명하는 것
		- Ex) 캠페인을 게시한다, 트랜잭션을 롤백한다, 주문을 제출한다.
	- 액터가 특정 커맨드를 실행
		- 액터는 고객, 관리자, 편집자 등 여러 페르소나가 될 수 있음
		- 액터는 커맨드의 행위자
	- 대부분의 커맨드는 액터가 없음
6. 정책
	- 자동화 정책(automation policy)
		- 이벤트가 커맨드의 실행을 시작하는 시나리오
7. 읽기 모델
	- 액터가 커맨드를 실행을 위한 의사결정을 내릴 때 사용하는 시각적 데이터
	- Ex) 스크린, 리포트, 알림
8. 외부시스템
	- 탐색중인 도메인에 포함되지 않는 모든 시스템
	- 해당 단계까지 완료시 모든 커맨드는 액터, 정책, 외부시스템이 호출하는 관계로 표시됨
9. 애그리게이트
	- 커맨드와 이벤트를 포함하는 모델
10. 바운디드 컨텍스트
	- 서로 연관된 애그리게이트를 찾음
		- 기능이 연관되거나 같은 정책으로 이어진 경우
		- 애그리게이트 그룹은 바운디드 컨텍스트 경계의 자연스러운 후보가 됨

## 1.3. 이벤트스토밍을 사용하는 경우
1. 유비쿼터스 언어 구축하기
	- 그룹에서 비즈니스 프로세스 모델을 구축할 때 용어 통일을 위해 사용
2. 비즈니스 프로세스 모델링
	- 이벤트스토밍 세션은 비즈니스 프로세스 모델을 구축하는데 효과적임
	- 애그리게이트와 바운디드 컨텍스트의 경계를 발견하는데 효과적인 방법
3. 새로운 비즈니스 요구사항 탐색하기
	- 모든 참가자가 새로운 기능에 대한 생각 동기화
	- 비즈니스 요구사항에 없는 예외 케이스 발견
4. 도메인 지식 복구하기
	- 시간에 따라 도메인 지식은 손실됨
	- 현대화가 필요한 레거스시스템에 효과적
5. 존재하는 비즈니스 프로세스의 개선 방법 탐색하기
	- 비즈니스 프로세스를 엔드-투-엔드 관점에서 바라보게함
		- 이벤트 스토밍은 다양한 참가자(UX, 도메인 전문가, 엔지니어링)들이 참여하기 때문
6. 새로운 팀원의 훈련
