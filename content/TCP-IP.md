# 1. TCP / IP

## 1.1. 목적
- 운영체제와 무관하게 통신을 위함
- 최초 TCP/IP 개발시 유닉스 전용
	- Then) 데이터 포맷은 유닉스 체계 사용
- 라우팅 가능
	- [[패킷교환 방식 (Packet Switching)]] 채택
- 망 중립성과 개방성
	- 자율적 관리
	- 데이터 송수신자의 자유도 확보

## 1.2. 특징
- 현대 인터넷은 TCP/IP기반
	- [[OSI-7계층 (OSI-7 Layer)]]는 개념적 모델
	- 원격 로그인/ 대화형 파일 전송/ 전자 메일 등 지원
- 클라이언트 서버 구조
	- Socket 프로그래밍

### 1.3.1. TCP Header
| 필드         | 크기 (비트) | 내용                          | 상세 설명                                             |
| ---------- | ------- | --------------------------- | ------------------------------------------------- |
| 송신자의 포트 번호 | 16      | 데이터를 보내는 애플리케이션의 포트 번호      | TCP로 연결되는 가상 회선 양단의 송수신 프로세스에 할당되는 포트 주소          |
| 수신자의 포트 번호 | 16      | 데이터를 받을 애플리케이션의 포트 번호       | TCP로 연결되는 가상 회선 양단의 송수신 프로세스에 할당되는 포트 주소          |
| 순서 번호      | 32      | 송신자가 지정하는 순서 번호 (바이트 수 기준)  | 송신자가 지정하는 순서 번호로, 전송되는 바이트 수에 따라 증가               |
| 응답 번호      | 32      | 수신 완료된 데이터 순서 번호 (바이트 수 기준) | 수신 프로세스가 제대로 수신한 바이트 수를 응답하기 위해 사용                |
| 데이터 오프셋    | 4       | 데이터의 시작 위치                  | TCP 세그먼트의 시작 위치를 기준으로 데이터의 시작 위치를 표현 (TCP 헤더의 크기) |
| 예약 필드      | 6       | 사용하지 않음                     | 아직 사용되지 않지만 이후 확장을 위해 예약된 필드                      |
| 제어 비트      | 6       | SYN, ACK, FIN 등의 제어 번호      | 별도 설명 참조                                          |
| 윈도우 크기     | 16      | 수신자에서 수신할 수 있는 데이터의 크기      | 수신 윈도우의 버퍼 크기를 지정할 때 사용                           |
| 체크섬        | 16      | 데이터 오류 검사에 사용               | TCP 세그먼트에 포함되는 프로토콜 헤더와 데이터에 대한 오류 검출 용도          |
| 긴급 위치      | 16      | 긴급하게 처리할 데이터의 위치            | 긴급 데이터를 처리하기 위함, URG 플래그 비트가 지정된 경우에만 유효          |
#### 제어 비트 종류

| 제어비트    | 이름             | 의미           | 설명                                                           |
| ------- | -------------- | ------------ | ------------------------------------------------------------ |
| **URG** | Urgent         | 긴급 데이터 존재 여부 | Urgent Pointer 필드가 유효함을 의미. 수신 측은 우선 처리해야 할 긴급 데이터가 있음을 인지함. |
| **ACK** | Acknowledgment | 응답 번호 유효     | ACK 번호 필드가 유효함을 의미. 상대에게 데이터 수신 확인(acknowledgment)을 보냄.      |
| **PSH** | Push           | 즉시 상위계층 전달   | 데이터를 버퍼링하지 않고 즉시 애플리케이션 계층으로 전달하도록 요청하는 제어비트.                |
| **RST** | Reset          | 연결 강제 초기화    | 비정상적인 상황 발생 시 TCP 연결을 즉시 끊고 재설정할 때 사용.                       |
| **SYN** | Synchronize    | 연결 설정        | 3-way handshake 과정에서 연결을 요청하고 초기 시퀀스 번호를 교환할 때 사용.           |
| **FIN** | Finish         | 연결 종료        | 더 이상 보낼 데이터가 없음을 의미. TCP 연결 종료 절차(4-way handshake)에 사용.      |

### 1.3.2. IP Header
| 필드 이름                                         | 크기 (비트) | 설명                                                                          |
| --------------------------------------------- | ------- | --------------------------------------------------------------------------- |
| **Version**                                   | 4       | IP 프로토콜 버전 (IPv4는 4)                                                        |
| **IHL (Internet Header Length)**              | 4       | IP 헤더의 길이 (4바이트 단위)                                                         |
| **DSCP (Differentiated Services Code Point)** | 6       | - 서비스 품질(QoS) 제어를 위한 필드<br>- 우선 순위를 결정(지연률, 전송률, 신뢰성 중 1) 거의 사용 X           |
| **ECN (Explicit Congestion Notification)**    | 2       | 혼잡 알림을 위해 사용되는 필드                                                           |
| **Total Length (packet length)**              | 16      | 헤더 + 데이터 전체 길이(바이트 단위)                                                      |
| **Identification**                            | 16      | - 패킷 단편화(Fragmentation) 시 조각들을 식별하기 위한 값<br>- 상위 계층에서 분할하여 번호를 부여함          |
| **Flags**                                     | 3       | - 단편화 관련 제어 비트 (DF, MF)<br>- DF: 패킷 분할을 막음<br>- MF: 분할된 패킷이 이어지는지, 종료되는지 표시 |
| **Fragment Offset**                           | 13      | 단편이 원본 데이터에서 어느 위치에 해당하는지 표시                                                |
| **Time To Live (TTL)**                        | 8       | 패킷이 네트워크에서 살아있을 수 있는 최대 홉 수                                                 |
| **Protocol**                                  | 8       | 상위 계층 프로토콜 지정 (TCP=6, UDP=17 등)                                             |
| **Header Checksum**                           | 16      | 헤더 오류 검출을 위한 체크섬                                                            |
| **Source IP Address**                         | 32      | 패킷을 보내는 호스트의 IP 주소                                                          |
| **Destination IP Address**                    | 32      | 패킷을 받는 호스트의 IP 주소                                                           |
| **Options (선택적)**                             | 가변      | 특수 기능을 위한 확장 영역 (일반적으로 사용되지 않음)                                             |
| **Padding**                                   | 가변      | 헤더 길이를 32비트(4바이트) 배수로 맞추기 위한 여백                                             |
- IHL: 4바이트 단위에 부족한 부분은 Padding필드 사용
