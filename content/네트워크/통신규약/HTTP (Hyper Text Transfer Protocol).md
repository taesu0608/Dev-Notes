# 1. HTTP
- 서버 - 클라이언트가 서로 데이터를 주고받기 위해 사용되는 통신 규약
- 여러 종류의 데이터 취급
	1. [[HTML]], TEXT
	2. IMAGE, 음성, 영상, 파일
	3. JSON, XML(API)
	- 거의 모든 형태의 데이터 전송 가능
Cf) HTTP 외 인터넷 기반 서비스
- Email. FTP, DNS, NEWS

# 2. HTTP 발전과정
| 버전           | 발표 연도 | 주요 변화 및 특징                                                                                                                                                                                                                                       |
| ------------ | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **HTTP/0.9** | 1991  | - `GET` 메서드만 지원- HTTP 헤더 없음                                                                                                                                                                                                                      |
| **HTTP/1.0** | 1996  | - `메서드`, `헤더`, `상태 코드` 추가- 요청 헤더에 HTTP 버전 명시- 응답 헤더에 상태 코드와 `Content-Type` 추가 → HTML 외 다양한 파일 전송 가능- **단기 커넥션**: 하나의 연결당 1 요청, 1 응답만 처리 → 연결 반복으로 인한 성능 저하 및 서버 부하 증가                                                                            |
| **HTTP/1.1** | 1997  | - 현재까지 가장 널리 사용되는 버전- 대부분의 HTTP 기능 구현- **Persistent Connection**: 지정된 timeout 동안 연결을 유지하여 다중 요청 처리 가능- **Pipelining**: 응답을 기다리지 않고 순차적으로 여러 요청을 전송 → 지연 시간 단축- **Head of Line Blocking** 문제 존재 (선행 요청 지연 시 후행 요청도 지연됨)- 1.1 이후 버전들은 주로 성능 개선에 초점 |
| **HTTP/2.0** | 2015  | - **바이너리 프레이밍 계층** 도입 → 파싱 및 전송 속도 향상, 오류율 감소- **멀티플렉싱** 지원 → 한 연결 내에서 여러 요청/응답 동시 처리- **HPACK 압축**으로 헤더 중복값 제거 및 전송 효율 개선                                                                                                                       |
| **HTTP/3.0** | 2019~ | - **TCP 대신 UDP 기반 QUIC 프로토콜** 사용- 기존 TCP의 고질적 지연(RTT) 문제 해결- 연결 설정 속도 향상 및 패킷 손실 시 복구 효율 개선                                                                                                                                                      |

## 3.2. HTTP의 특징
1. HTTP의 무상태성 (Stateless)
	- **무상태성(Stateless)**: 클라이언트와 서버 사이에 상태를 유지하지 않는다.
	- 장점
		- 서버 확장성 높음 (Scale Out)
	- 단점
		- 클라이언트가 추가 데이터 전송(메모리 증가)
			- 쿠키, 세션, 토큰 사용이 필수적
---
### 3.2.1. Cf) Difference between 상태유지(Stateful) and 무상태(Stateless)
1. **상태유지(Stateful)**
	- 서버가 클라이언트의 상태 보존
		- 실시간 연결 유지 (Real-time Connection)와는 다름
2. **무상태(Stateless)**
	- 서버가 클라이언트의 상태 보존 X
		- 클라이언트의 토큰으로 회원 정보 관리
	- 서버 호출 시점이 자유롭기에 서버의 수평확장(Scale Out)에 유리
	- 상태유지(Stateful)보다 많은 데이터 사용
---
2. HTTP의 비연결성 (Connectionless)
	- HTTP는 기본이 연결을 유지하지 않는 모델
	- 다수 접속시 실제 서버에서 처리하는 요청은 적음
