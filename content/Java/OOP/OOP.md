### 2.1.2. 접근 지정자(Access Modifier)
- 캡슐화를 이루기 위한 Java의 방법
- 접근 지정자는 **클래스** 제어 관점

| 접근 지정자    | 동일 클래스 | 동일 패키지 | 상속  | 다른 패키지 |

| **default**   | O      | O      | X   | X      |
| **private**   | O      | X      | X   | X      |

#### Q - 1) 왜 모든 접근 지정자들이 동일 클래스의 접근이 허용일까?
> 객체 지향 언어는 취급 단위가 객체 즉 클래스 기반이므로, 한 클래스 내의 접근 제어를 다루지 않는다.

#### Q - 2) private의 사용 목적은 무엇일까?
> 완전한 캡슐화

#### Q - 3) 왜 default는 상속 클래스의 접근을 제한하였을까?
> 상속의 관계는 특수한 관계이기 때문에 개발 Nudge을 고려한 것 같다.

# 1. 캡슐화 (Encapsulation)

### 정의
- 객체의 **속성(필드)**과 **행동(메서드)** 을 하나의 단위로 묶고, 외부에서의 직접 접근을 **제한**하는 개념이다.
- 주로 `private` 접근 제한자와 `getter`, `setter`를 통해 구현된다.

### 목적
- 내부 구현을 숨기고(public API만 공개) → **보안성, 유지보수성 향상**
- 잘못된 접근으로 인한 객체의 무결성 훼손을 방지

### 예시
```java
public class User {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

##  2. 상속 (Inheritance)

### 정의
- 기존 클래스(부모)의 **필드와 메서드를 자식 클래스가 물려받는 기능**  
- 코드 재사용성과 확장성을 높여준다.

### 특징
- `extends` 키워드로 클래스 상속
- 자바에서는 **다중 클래스 상속은 불가**, 인터페이스는 다중 구현 가능

### 예시
```java
public class Animal {
    void speak() { System.out.println("동물 소리"); }
}

public class Dog extends Animal {
    void bark() { System.out.println("멍멍"); }
}
```

##  3. 추상화 (Abstraction)

### 정의
- 객체의 **공통적인 특성과 동작만 정의하고, 구체적인 구현은 감추는 개념**

### 보완 설명
- `abstract class` 또는 `interface`를 통해 추상화 구현
- 사용자는 **"무엇을 할 수 있는지"
- 만 알면 되고, "어떻게 하는지"는 몰라도 된다**

### 예시
```java
interface Vehicle {
    void move(); // 추상적 기능 정의
}

class Car implements Vehicle {
    public void move() {
        System.out.println("자동차가 움직인다.");
    }
}
```

## 4. 다형성 (Polymorphism)

### 정의
- 같은 타입(부모 타입, 인터페이스)으로 다양한 객체를 사용하되, **동작은 객체별로 다르게 실행되는 특성**

### 핵심
- **인터페이스나 부모 타입을 통한 업캐스팅 + 오버라이딩된 메서드 호출**
- 대표적인 객체지향의 확장성 수단

### 너의 설명 기반 해석
> 인터페이스는 실질적인 구현을 물려받지 않고도 여러 인터페이스를 동시에 구현할 수 있어 다양한 객체에 대해 일관된 방식으로 메서드를 호출할 수 있게 한다.

### 예시
```java
Vehicle car = new Car();
Vehicle ship = new Ship();

car.move();   // Car의 move() 실행
ship.move();  // Ship의 move() 실행
```
